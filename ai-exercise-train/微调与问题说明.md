# 运动识别微调与常见问题说明

## 一、为什么检测不到深蹲个数？为什么误检成其他运动？

### 1. 现象分析

你的 `shendun.mp4` 输出：
- **高抬腿 3.3秒** | **深蹲 0.3秒** | **弓箭步 3.4秒**，且次数均为 0

原因主要有三点：

| 问题 | 说明 |
|------|------|
| **误分类** | 模型把深蹲误判成高抬腿、弓箭步（姿态相似，训练数据与你的视频有差异） |
| **频繁切换** | 每误判一次就切换运动类型，计数器被重置，无法积累次数 |
| **时间过短** | 深蹲只被识别 0.3 秒（约 9 帧），动作还未完成就被切走 |

### 2. 已做的脚本改进

`run_video.py` 已增加：

- **`--conf`**：提高检测置信度阈值，减少误检（默认 0.5，可试 0.6~0.7）
- **`--stable-frames`**：同一运动需连续检测 N 帧才切换（默认 15 帧≈0.5 秒）

推荐先尝试：

```powershell
python run_video.py shendun.mp4 --conf 0.6 --stable-frames 20 --output result.mp4
```

## 二、四项运动的训练结果

数据集 `exercise-ekbld-kjve3` 共 4 类：

| 类别 | 中文 | 训练集表现（约） |
|------|------|------------------|
| high_jumps | 高抬腿 | mAP50 ~92% |
| jumping_jacks | 开合跳 | mAP50 ~92% |
| lunges | 弓箭步 | mAP50 ~92% |
| squats | 深蹲 | mAP50 ~92% |

**整体指标**（第 100 轮）：Precision 89%、Recall 88%、mAP50 92%。

验证集与你的实拍视频存在差异（角度、光线、动作幅度），因此会出现误检和漏检。

## 三、微调方式

### 方案 A：调参数（无需重新训练）

1. **提高置信度**：
   ```powershell
   python run_video.py video.mp4 --conf 0.65
   ```
   误检多时提高，漏检多时降低。

2. **提高切换稳定性**：
   ```powershell
   python run_video.py video.mp4 --stable-frames 25
   ```
   同一运动需连续 25 帧才切换。

3. **调次数计数**：编辑 `config/exercise_config.yaml`：

   ```yaml
   rep_count_configs:
     squats:
       kpts: [12, 14, 16]   # 髋-膝-踝
       up_angle: 165        # 站直时膝角 (可试 155~170)
       down_angle: 85       # 蹲下时膝角 (可试 80~100)
   ```

   - 次数偏少：把 `down_angle` 调大（如 95），更容易触发
   - 次数偏多：把 `down_angle` 调小（如 80），要求蹲得更低

4. **用输出视频检查**：
   ```powershell
   python run_video.py shendun.mp4 --output result.mp4 --no-display
   ```
   查看 `result.mp4` 中每帧的类别标注是否合理。

---

### 方案 B：加数据再训练（效果最好）

用你自己的视频扩充数据集，重点增加深蹲：

1. **准备深蹲素材**：拍摄不同角度、光线、人的深蹲视频。
2. **导出帧并标注**：
   - 用 Roboflow 上传图片，框选人物并标为 "squats"
   - 或在 [Roboflow Universe](https://universe.roboflow.com) 找更多深蹲数据，与现有数据合并
3. **重新训练**：
   ```powershell
   set EPOCHS=120
   python scripts/train.py
   ```

---

### 方案 C：用现有模型做“专属微调”

1. 把你的深蹲视频切帧，用 Roboflow 标注为 "squats"。
2. 与原 `exercise-ekbld-kjve3` 合并，生成新数据集。
3. 在 `scripts/train.py` 中指定 `model=runs/exercise_train/weights/best.pt`，在该模型上继续训练。

## 四、次数为 0 的常见原因

| 原因 | 处理 |
|------|------|
| 检测类别频繁切换 | 使用 `--stable-frames 20` |
| 姿态关键点不可见 | 保证全身在画面内，正面或侧面均可 |
| 角度阈值不合适 | 在 config 中调整 `up_angle`、`down_angle` |
| 视频过短 | 单次运动至少持续约 1 秒才有机会完成一次计数 |

## 五、快速自检命令

```powershell
# 1. 高置信度 + 稳定切换，保存结果
python run_video.py shendun.mp4 --conf 0.65 --stable-frames 20 -o result.mp4 --no-display

# 2. 查看结果视频，确认类别和次数显示是否合理
```

若 `result.mp4` 中类别基本正确，但次数仍为 0，优先修改 `config/exercise_config.yaml` 中的 `squats` 角度参数。
