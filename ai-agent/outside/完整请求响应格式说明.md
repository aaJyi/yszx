# 完整请求响应格式说明

## 一、整体流程

```
前端（uni-app） → 后端Controller → 后端Service → 智能体接口 → 后端Service → 后端Controller → 前端（uni-app）
```

---

## 二、前端发送给后端的请求格式

### 1. 请求URL
```
POST http://localhost:8080/home-chat/ask
```
或（微信小程序环境）：
```
POST https://65a7cb0.r16.vip.cpolar.cn/home-chat/ask
```

### 2. 请求头
```javascript
{
  'userId': '2',              // 用户ID（从本地存储获取）
  'token': 'xxx',             // 用户token（可选）
  'Content-Type': 'application/json'
}
```

### 3. 请求体JSON格式

**示例1：首次对话（无历史）**
```json
{
  "question": "你好",
  "userId": 2,
  "history": []
}
```

**示例2：带对话历史**
```json
{
  "question": "我的血压正常吗？",
  "userId": 2,
  "history": [
    {
      "role": "user",
      "content": "你好"
    },
    {
      "role": "assistant",
      "content": "您好！我是AI健康助手，有什么健康问题可以咨询我。"
    }
  ]
}
```

### 4. 前端代码示例（实际发送）

```javascript
uni.request({
  url: `${config.baseUrl}/home-chat/ask`,
  method: 'POST',
  data: {
    question: question,           // 用户输入的问题
    userId: this.userId,          // 用户ID
    history: history              // 对话历史（最近10条）
  },
  header: {
    'userId': userInfo.userId,
    'token': token || '',
    'Content-Type': 'application/json'
  },
  success: (res) => {
    // 处理响应
  }
})
```

### 5. 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| question | String | 是 | 用户提问内容 |
| userId | Number | 是 | 用户ID |
| history | Array | 否 | 对话历史，格式：`[{"role": "user/assistant", "content": "内容"}]` |

## 三、后端Controller接收的请求格式

### 1. 接收的请求（与前端发送的格式一致）

**接口**：`POST /home-chat/ask`

**请求体**：
```json
{
  "question": "你好",
  "userId": 2,
  "history": [
    {
      "role": "user",
      "content": "之前的问题"
    },
    {
      "role": "assistant",
      "content": "之前的回答"
    }
  ]
}
```

### 2. Controller处理逻辑

```java
@PostMapping("/ask")
public Result<Map<String, Object>> ask(@RequestBody Map<String, Object> requestBody) {
    // 1. 从请求体中提取参数
    String question = (String) requestBody.get("question");
    Long userId = 从requestBody或UserContext获取;
    Object history = requestBody.get("history");
    
    // 2. 调用Service层
    String answer = consultationService.chat(userId, question, history);
    
    // 3. 返回结果
    return Result.success("对话成功", {
        "answer": answer,
        "question": question,
        "userId": userId
    });
}
```

### 3. Controller返回给前端的格式

**成功响应**：
```json
{
  "code": 200,
  "message": "对话成功",
  "data": {
    "answer": "您好！我是AI健康助手，有什么健康问题可以咨询我。",
    "question": "你好",
    "userId": 2
  }
}
```

**失败响应**：
```json
{
  "code": 400,
  "message": "提问内容不能为空",
  "data": null
}
```

## 五、智能体接收的请求格式

### ⚠️ 重要：智能体开发程序员收到的格式

智能体接收到的JSON格式与后端Service发送的格式**完全一致**。

### 1. 接收的请求

**URL**：`POST https://3c1d06ab.r30.cpolar.top/chat`

**请求头**：
```http
Content-Type: application/json
```

**请求体**（与后端Service发送的格式一致）：
```json
{
  "userId": 2,
  "question": "你好",
  "history": [
    {
      "role": "user",
      "content": "之前的问题"
    },
    {
      "role": "assistant",
      "content": "之前的回答"
    }
  ],
  "userHealthData": {
    "userId": 2,
    "rawHealthDataList": [...],
    "healthArchives": [...]
  }
}
```

### 2. 智能体需要处理的字段

- **userId**：用户ID，可用于查询用户相关信息
- **question**：当前用户的问题，需要回答的内容
- **history**：对话历史，可用于上下文理解

  - `rawHealthDataList`：原始健康数据列表（体检报告等）
  - `healthArchives`：健康档案列表（包含所有从表数据）

## 六、智能体返回给后端的格式

### ⚠️ 重要：智能体开发程序员需要返回的格式

### 1. 响应状态码
- `200 OK`：成功
- `400 Bad Request`：请求格式错误
- `500 Internal Server Error`：服务器错误

### 2. 成功响应格式（推荐格式1 - 最优先）

```json
{
  "answer": "您好！我是AI健康助手，有什么健康问题可以咨询我。根据您的健康档案，我注意到您有一些健康指标需要关注..."
}
```

### 3. 成功响应格式（推荐格式2）

```json
{
  "data": {
    "answer": "您好！我是AI健康助手，有什么健康问题可以咨询我..."
  }
}
```

### 4. 成功响应格式（推荐格式3）

```json
{
  "message": "您好！我是AI健康助手，有什么健康问题可以咨询我..."
}
```

### 5. 成功响应格式（推荐格式4）

```json
{
  "content": "您好！我是AI健康助手，有什么健康问题可以咨询我..."
}
```

### 6. 错误响应格式

```json
{
  "error": "错误信息",
  "code": 400
}
```

### 7. 后端解析逻辑

后端会按以下优先级解析回答：
1. ✅ `answer` 字段（最优先）
2. ✅ `data.answer` 字段
3. ✅ `message` 字段
4. ✅ `content` 字段

如果都不匹配，会返回默认错误消息。

## 十一、当前问题分析

### 错误信息
```
智能体对话接口返回客户端错误，状态码：405 METHOD_NOT_ALLOWED，响应：{"detail":"Method Not Allowed"}
```

### 可能的原因

1. **URL路径错误**
   - 当前配置：`ai.agent.chat.url=https://3c1d06ab.r30.cpolar.top/chat`
   - 如果智能体接口路径不是 `/chat`，需要修改配置

2. **HTTP方法错误**
   - 当前使用：`POST`
   - 如果智能体接口只支持 `GET`，需要修改代码

3. **接口不存在**
   - 该URL可能不是对话接口
   - 需要确认智能体接口的正确URL

### 解决方案

1. **确认智能体接口URL**
   - 询问智能体开发程序员正确的接口URL
   - 确认路径（如：`/chat`、`/api/chat`、`/v1/chat` 等）

2. **确认HTTP方法**
   - 确认智能体接口支持的HTTP方法（GET/POST）

3. **修改配置**
   - 在 `application.properties` 中配置正确的完整URL：
   ```properties
   ai.agent.chat.url=https://3c1d06ab.r30.cpolar.top/正确的路径
   ```

4. **测试接口**
   - 使用Postman或curl测试智能体接口
   - 确认请求格式和响应格式

## 十三、总结

### 数据流向

```
前端 → 后端Controller → 后端Service → 智能体 → 后端Service → 后端Controller → 前端
```

### 关键格式

1. **前端发送**：`{question, userId, history}`
2. **后端转发**：`{userId, question, history, userHealthData}`
3. **智能体返回**：`{answer}` 或 `{data: {answer}}`
4. **后端返回**：`{code, message, data: {answer, question, userId}}`

### 关键配置

```properties
# application.properties
ai.agent.chat.url=https://3c1d06ab.r30.cpolar.top/chat
```

### 关键代码位置

- **前端**：`康乐医疗/pages/index/index.vue` - `sendChatMessage()` 方法
- **后端Controller**：`HomeChatController.java` - `ask()` 方法
- **后端Service**：`ConsultationServiceImpl.java` - `chat()` 方法
