# 智能体开发程序员调用接口文档

## 一、整体业务流程

### 1. 完整流程

```
用户上传体检报告（PDF/图片）
  ↓
后端保存到 raw_health_data 表
  ↓
后端结构化解析，保存到 health_archive 及相关拆表
  ↓
后端调用智能体服务进行AI分析
  ↓
智能体开发程序员分析完成后，调用接口提交结果
  ↓
后端保存分析结果到 health_ai_analysis 表
  ↓
后端根据规则引擎自动生成建议到 health_recommendation 表
  ↓
小程序前端展示分析结果和建议
```

### 2. 数据流关系图

```
t_user (用户表)
  ↓
raw_health_data (原始健康数据 - 用户上传的PDF/图片)
  ↓
health_archive (结构化健康档案)
  ↓
health_ai_analysis (AI分析结果 - 模型结论层)
  ↓
health_recommendation (健康建议 - 用户可见层)
  ↓ (由规则引擎生成)
health_recommendation_rule (建议规则 - 规则引擎配置)
```

## 二、智能体开发程序员完整工作流程

### 工作流程概览

智能体开发程序员需要完成以下步骤：

```
1. 调用接口获取用户完整数据（只需传递userId）
   GET /health-ai-analysis/data/user/{userId}
   ↓ 后端自动查询：该用户的所有原始数据 + 所有健康档案及其从表数据
   ↓
2. 基于获取的数据进行AI分析
   ↓ 分析健康档案数据 + 原始体检报告数据
   ↓
3. 生成分析结果JSON（analysisResult）
   ↓
4. 生成健康建议JSON（recommendations，可选）
   ↓
5. 调用提交接口提交分析结果（只需传递userId和分析结果，无需传递健康档案数据）
   POST /health-ai-analysis/submit/user/{userId}
```

### Step 1: 获取用户完整数据（一次接口调用获取所有数据）

**简化设计**：智能体只需要传递 `userId`，后端自动查询并返回：
- 该用户的所有原始健康数据（`raw_health_data` 表）
- 该用户的所有健康档案（`health_archive` 表）
- 每个档案的所有从表数据（个人健康标识、用户基本信息、过敏史、既往史等）

**接口地址**：
```
GET https://43d51924.r16.vip.cpolar.cn/health-ai-analysis/data/user/{userId}
```

### Step 2: AI分析处理

智能体基于以下数据进行AI分析：

**输入数据来源**：
1. **健康档案结构化数据**（从Step 1获取）
   - 个人基本信息（姓名、年龄、性别等）
   - 健康标识（年龄组、慢病、血型、体重状况等）
   - 既往史、家族史、过敏史、遗传病史等
   - 用户基本信息（联系方式、职业、婚姻状况等）
   
2. **原始体检报告数据**（从Step 2获取）
   - 体检报告的PDF/图片文件
   - OCR提取的文本内容
   - 图像识别提取的数据指标

**AI分析关键点**：
- **解析体检报告**：使用OCR/NLP技术提取体检指标数据
  - 血液指标（血脂、血糖、血常规等）
  - 影像学指标（B超、X光等）
  - 体格检查指标（身高、体重、血压等）
  
- **结合健康档案信息**：
  - 如果有**家族史**（如高血脂家族史），相关指标的风险等级应提高
  - 如果有**既往史**（如糖尿病），相关指标需要特别关注
  - 如果有**过敏史**，需要在分析中考虑
  - 根据**年龄组**（0-6岁儿童、65岁以上、孕产妇）调整参考范围
  
- **进行多维度分析**：
  - **代谢健康维度**：BMI、血脂、血糖等
  - **血糖控制维度**：空腹血糖、糖化血红蛋白等
  - **泌尿系统维度**：尿常规指标
  - **心血管维度**：血压、心电图等
  - 根据检测到的异常指标，生成相应的维度分析

- **计算综合评估**：
  - 根据所有维度分析结果，计算整体健康评分（0-100）
  - 确定整体风险等级（低、中、高、极高）
  - 提取关键风险点
  - 生成分析摘要

**分析示例**：
```
场景：体检报告显示BMI=27.1（超重），甘油三酯=4.25（偏高）
      健康档案显示：有高血脂家族史（家族史）

分析过程：
1. 识别异常指标：BMI、甘油三酯
2. 结合家族史信息：有高血脂家族史 → 代谢异常风险提高
3. 生成维度分析：
   - dimensionCode: "METABOLIC"
   - riskLevel: "高"（因为有家族史，风险等级提高）
   - evidence: [BMI=27.1, 甘油三酯=4.25]
   - interpretation: "体重指数及血脂指标高于参考范围，结合家族史，提示存在代谢异常高风险。"
```

**重要原则**：
- 必须基于**体检报告的实际数据**进行分析
- 必须结合**健康档案的既往史、家族史**等信息
- 每个维度必须有**证据支撑**（evidence）
- 分析结论必须**可解释**（interpretation）

### Step 3: 生成分析结果JSON和建议

基于AI分析结果，构建符合接口要求的JSON格式：

**关键点**：
- `dimensionAnalysis`：根据体检报告中的异常指标，结合健康档案信息，生成多个维度的分析
- `overallAssessment`：综合所有维度，给出整体评估
- `abnormalIndicators`：提取所有异常指标
- `evidence`：每个维度必须有证据支撑（指标、值、参考范围）
- `recommendations`：**根据分析结论、原始数据和基本信息生成较长的健康建议**
- `extendedData`：**必须为5张表的所有字段提供数据**（详见下方说明）

## 三、提交分析结果接口

### 接口地址

```
POST https://43d51924.r16.vip.cpolar.cn/health-ai-analysis/submit/user/{userId}
```

**重要说明**：
- `userId` **从路径参数获取**，无需在JSON中传递
- 后端会将路径参数中的 `userId` 保存到：
  - `health_ai_analysis` 表的 `user_id` 字段
  - `health_recommendation` 表的 `user_id` 字段
- 所有保存的记录都会使用同一个 `userId`（来自路径参数）

### 请求头

```
Content-Type: application/json
```

### 请求参数说明

**路径参数**：
- `userId`（必填）：用户ID，将保存到数据库的所有相关表中

**JSON参数**（请求体）：

**简化设计**：只需传递分析结果和建议，无需传递健康档案数据（后端已存储）

**必填字段**：
- `archiveId`：档案ID（从Step 1获取的数据中获取）
- `sourceRawId`：原始数据ID（触发分析的体检报告ID，从Step 1获取的数据中获取）
- `modelName`：模型名称
- `modelVersion`：模型版本
- `analysisResult`：AI分析结果

**可选字段**：
- `recommendations`：智能体生成的健康建议列表
  - 如果提供了 `recommendations`，系统会优先保存智能体生成的建议
  - 如果没有提供或保存失败，系统会使用规则引擎自动生成建议
  - **注意**：所有建议的 `userId` 会自动使用路径参数中的 `userId`
- `analysisResult.extendedData`：扩展数据（**必填**）
  - ⚠️ **重要**：智能体分析后，**必须**为以下5张表的所有字段提供数据（系统自动生成的字段除外）：
    - `lifestyleStatus`：生活方式状态表数据（health_lifestyle_status）**34个字段必填**
    - `systemSymptomScreening` 或 `systemDiseaseScreening`：系统疾病与症状筛查表数据（health_system_disease_screening）**10个字段必填**
    - `psychologicalAssessment`：心理评估表数据（health_psychological_assessment）**13个字段必填**
    - `socialBackground` 或 `socialRelationshipAssessment`：社会关系评估表数据（health_social_relationship_assessment）**7个字段必填**
    - `physicalExamination`：体格检查表数据（health_physical_examination）**80个字段必填**
  - 系统会自动将extendedData中的数据映射并保存到对应的数据库表中
  - 如果某个字段在原始数据中无法获取，请使用 `null`，但**必须包含该字段**

**JSON请求体**：
| 字段 | 类型 | 说明 |
|------|------|------|
| archiveId | Integer | 档案ID（必填，从Step 1获取的数据中获取） |

**建议内容要求**：
- 内容应该**较长且详细**
- 必须基于AI分析结论、原始数据和健康档案信息
- 提供具体的行动建议
- 必须符合医疗合规要求（不能诊断、不能开药）

#### extendedData（扩展数据）- **必填**

⚠️ **重要**：智能体分析后，**必须**为以下5张表的所有字段提供数据（系统自动生成的字段除外），系统会自动保存到对应的数据库表中。

**系统自动生成的字段（不需要智能体提供）**：
- 所有表的ID字段（如 `lifestyleId`、`screeningId`、`assessmentId`、`examId`）
- `archiveId`（由系统自动设置）
- `createTime`、`updateTime`（由系统自动生成）

**智能体必须提供的表**：

| 字段名 | 类型 | 说明 | 必填字段数 |
|--------|------|------|-----------|
| lifestyleStatus | Object | 生活方式状态表数据（health_lifestyle_status） | **34个字段** |
| systemSymptomScreening 或 systemDiseaseScreening | Object | 系统疾病与症状筛查表数据（health_system_disease_screening） | **10个字段** |
| psychologicalAssessment | Object | 心理评估表数据（health_psychological_assessment） | **13个字段** |
| socialBackground 或 socialRelationshipAssessment | Object | 社会关系评估表数据（health_social_relationship_assessment） | **7个字段** |
| physicalExamination | Object | 体格检查表数据（health_physical_examination） | **80个字段** |

**重要说明**：
- ⚠️ **必须为每张表的所有字段提供数据**（系统自动生成的字段除外）
- 字段名需要与实体类的字段名对应（驼峰命名）
- 系统会自动将Map数据映射到对应的实体类并保存到数据库
- 如果某个字段在原始数据中无法获取或不存在，请使用 `null`，但**必须包含该字段**
- 所有扩展数据都会关联到对应的 `archiveId`

**字段值类型说明**：
- **SET类型字段**：可以多选，多个值用**逗号分隔**，如 `"0-素食,1-中餐,2-海鲜"`
- **ENUM类型字段**：只能单选，如 `"0-正常"`
- **Boolean类型字段**：使用 `true` 或 `false`
- **Integer类型字段**：使用数字，如 `3`
- **TEXT类型字段**：使用字符串，如 `"描述内容"` 或 `null`
- ⚠️ **所有枚举值必须严格按照数据库定义的值填写**（包含编码前缀，如 `"0-正常"` 而不是 `"正常"`）

## 五、系统自动处理逻辑

当智能体调用接口提交分析结果后，系统会按以下逻辑处理：

### 处理流程

```
1. 从路径参数获取 userId
   ↓
2. 保存分析结果到 health_ai_analysis 表
   ↓ analysis.setUserId(userId) → 保存到 health_ai_analysis.user_id
   ↓
3. 检查是否提供了 recommendations 字段
   ↓
   是 → 尝试保存智能体提交的建议
   ↓ recommendation.setUserId(analysis.getUserId()) → 保存到 health_recommendation.user_id
   ↓
   保存成功？ → 是：完成，返回成功
   ↓
   否 → 使用规则引擎生成建议（后备方案）
   ↓ recommendation.setUserId(analysis.getUserId()) → 保存到 health_recommendation.user_id
   ↓
   否（未提供recommendations） → 直接使用规则引擎生成建议
   ↓ recommendation.setUserId(analysis.getUserId()) → 保存到 health_recommendation.user_id
```

**重要**：
- ✅ `userId` 从路径参数获取
- ✅ 保存到 `health_ai_analysis` 表时，使用路径参数中的 `userId`
- ✅ 保存到 `health_recommendation` 表时，使用 `analysis.getUserId()`（与路径参数中的 `userId` 相同）
- ✅ 确保所有记录的 `userId` 都一致

### 智能体建议优先逻辑

**优先级1：智能体提交的建议**
- 如果请求中提供了 `recommendations` 字段且不为空
- 系统会尝试保存智能体生成的建议
- 建议内容应该**较长且详细**，基于：
  - AI分析结论（analysisResult）
  - 原始体检报告数据
  - 健康档案基本信息（既往史、家族史等）

**优先级2：规则引擎生成建议（后备方案）**
- 如果智能体没有提供 `recommendations` 字段
- 或者智能体提交的建议保存失败
- 系统会使用规则引擎自动生成建议

### 规则引擎匹配逻辑（后备方案）

- 系统会查询 `health_recommendation_rule` 表
- 匹配条件：`dimension_code` = 维度代码 且 `risk_level` = 风险等级
- 如果有多条规则匹配，会生成多条建议
- 建议按 `order_num` 排序

### 建议生成原则

**智能体建议的特点**：
- ✅ 内容较长且详细
- ✅ 结合具体的体检指标数据
- ✅ 结合健康档案的家族史、既往史等信息
- ✅ 提供具体的行动建议
- ✅ 符合医疗合规要求

**规则引擎建议的特点**：
- ✅ 使用预设的模板
- ✅ 标准化格式
- ✅ 作为后备方案确保一定有建议

智能体开发程序员的完整工作流程：

```
1. 获取用户完整数据（GET /health-ai-analysis/data/user/{userId}）

   ↓ - 该用户的所有原始健康数据（raw_health_data表）

   ↓ 结合：健康档案信息 + 原始体检报告数据
   ↓ 生成：维度分析、整体评估、异常指标等
   
3. 构建analysisResult JSON
   ↓ 格式：符合接口要求的JSON结构
   
4. 生成健康建议（基于分析结论、原始数据和基本信息）
   ↓ 生成：较长且详细的健康建议列表

   ↓ 系统：优先保存智能体建议，失败时使用规则引擎
   ↓ 返回：分析ID和保存的建议列表
```

✅ **灵活性**：

**智能体生成建议的输出**：
- `recommendations` 数组，每条建议包含：
  - `title`：建议标题
  - `content`：**较长且详细的建议内容**（200-500字）
  - `recommendationType`：建议类型
  - `priority`：优先级
  - `dimensionCode`：关联维度

**系统处理逻辑**：
- ✅ 如果提供了 `recommendations` 且保存成功 → 使用智能体建议
- ❌ 如果没有提供或保存失败 → 使用规则引擎生成（后备方案）
