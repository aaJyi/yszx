# 智能体插入健康总结和健康建议接口文档

## 一、接口概述

本接口用于智能体开发程序员提交AI分析结果，系统会自动：
1. 保存分析结果到 `health_ai_analysis` 表（健康总结表）
2. 保存健康建议到 `health_recommendation` 表（健康建议表）

**重要说明**：
- ✅ `userId` **从路径参数获取**，无需在JSON请求体中传递
- ✅ 系统会优先保存智能体提交的健康建议
- ✅ 如果智能体没有提交建议或保存失败，系统会使用规则引擎自动生成建议（后备方案）

---

## 二、接口详情

### 接口地址

```
POST /health-ai-analysis/submit/user/{userId}
```

### 完整URL示例

```
POST https://43d51924.r16.vip.cpolar.cn/health-ai-analysis/submit/user/2
```

### 请求方式

`POST`

### 请求头

```
Content-Type: application/json
```

### 请求参数

#### 路径参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 用户ID（将自动保存到 `health_ai_analysis.user_id` 和 `health_recommendation.user_id`） |

#### JSON请求体参数

**必填字段**：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| archiveId | Integer | 是 | 档案ID（从查询接口获取） |
| sourceRawId | Long | 是 | 原始数据ID（触发分析的体检报告ID，从查询接口获取） |
| modelName | String | 是 | 模型名称（如：health-ai-v1） |
| modelVersion | String | 是 | 模型版本（如：1.0.0） |
| analysisResult | Object | 是 | AI分析结果对象（详见下方说明） |

**可选字段**：

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| recommendations | List<Object> | 否 | 智能体生成的健康建议列表（可选）<br/>- 如果提供，系统会优先保存智能体建议<br/>- 如果不提供或保存失败，系统会使用规则引擎生成 |

**注意**：
- ❌ **不要在JSON请求体中传递 `userId`**，`userId` 从路径参数获取
- ✅ 系统会自动将路径参数中的 `userId` 保存到两个数据库表中

                          analysis_result: dict, recommendations: list = None):
    """
    提交AI分析结果和健康建议
    
    参数:
        user_id: 用户ID（路径参数）
        archive_id: 档案ID
        source_raw_id: 原始数据ID
        analysis_result: 分析结果对象
        recommendations: 健康建议列表（可选）

    # userId在URL路径中，将自动保存到数据库
    url = f"https://43d51924.r16.vip.cpolar.cn/health-ai-analysis/submit/user/{user_id}"
    
    # JSON请求体，不包含userId（userId在路径参数中）
    data = {
        "archiveId": archive_id,

        "modelName": "health-ai-v1",

        "analysisResult": analysis_result,

        "Content-Type": "application/json"

## 六、系统处理逻辑

### 处理流程

```
1. 从路径参数获取 userId
   ↓
2. 保存分析结果到 health_ai_analysis 表
   ↓ analysis.setUserId(userId) → 保存到 health_ai_analysis.user_id
   ↓
3. 检查是否提供了 recommendations 字段
   ↓
   是 → 尝试保存智能体提交的建议
   ↓ recommendation.setUserId(analysis.getUserId()) → 保存到 health_recommendation.user_id
   ↓
   保存成功？ → 是：完成，返回成功
   ↓
   否 → 使用规则引擎生成建议（后备方案）
   ↓ recommendation.setUserId(analysis.getUserId()) → 保存到 health_recommendation.user_id
   ↓
   否（未提供recommendations） → 直接使用规则引擎生成建议
   ↓ recommendation.setUserId(analysis.getUserId()) → 保存到 health_recommendation.user_id
```

### 智能体建议优先逻辑

**优先级1：智能体提交的建议**
- 如果请求中提供了 `recommendations` 字段且不为空
- 系统会尝试保存智能体生成的建议
- 建议内容应该**较长且详细**，基于：
  - AI分析结论（analysisResult）
  - 原始体检报告数据
  - 健康档案基本信息（既往史、家族史等）

**优先级2：规则引擎生成建议（后备方案）**
- 如果智能体没有提供 `recommendations` 字段
- 或者智能体提交的建议保存失败
- 系统会使用规则引擎自动生成建议

### 规则引擎匹配逻辑（后备方案）

- 系统会查询 `health_recommendation_rule` 表
- 匹配条件：`dimension_code` = 维度代码 且 `risk_level` = 风险等级
- 如果有多条规则匹配，会生成多条建议
- 建议按 `order_num` 排序

## 八、注意事项

### 1. userId处理说明

**重要**：`userId` 的处理流程

```
1. 智能体调用接口：POST /health-ai-analysis/submit/user/{userId}
   ↓
2. 后端从路径参数获取 userId
   ↓
3. 保存到 health_ai_analysis 表
   ↓ analysis.setUserId(userId) → 保存到 health_ai_analysis.user_id
   ↓
4. 保存到 health_recommendation 表
   ↓ recommendation.setUserId(analysis.getUserId()) → 保存到 health_recommendation.user_id
   ↓
5. 确保所有记录的 userId 都是路径参数中的值
```

**注意事项**：
- ✅ `userId` 必须从路径参数传递
- ✅ 后端自动将 `userId` 保存到两个数据库表中
- ❌ 不要在JSON请求体中传递 `userId`
- ✅ 所有保存的分析结果和建议都使用同一个 `userId`（来自路径参数）

### 2. 数据来源要求

⚠️ **重要**：`analysisResult` 中的所有数据必须基于：
- ✅ **体检报告的实际数据**（从原始数据中提取）
- ✅ **健康档案的历史数据**（从健康档案详情中获取）

❌ **不允许**：
- 凭空生成分析结果
- 不结合健康档案信息进行分析
- 忽略家族史、既往史等关键信息

✅ **必须**：
- 从体检报告中提取真实指标数据
- 结合健康档案的家族史、既往史等信息
- 每个维度分析必须有证据支撑

### 3. 健康建议生成要求

⚠️ **重要**：如果提供 `recommendations` 字段，建议内容必须：

✅ **必须**：
- 内容**较长且详细**（建议200-500字）
- 基于AI分析结论（analysisResult）
- 结合原始体检报告数据
- 结合健康档案基本信息（既往史、家族史等）
- 提供具体的行动建议
- 符合医疗合规要求

❌ **不允许**：
- 内容过于简短
- 不结合具体数据
- 不结合健康档案信息
- 违反医疗合规要求

### 4. 合规性要求

⚠️ **医疗合规**：
- 分析结果和建议必须符合医疗合规要求
- ❌ 不能诊断
- ❌ 不能开药
- ❌ 不能替代医生诊断
- ✅ 只能提示风险
- ✅ 建议关注和就医

**建议文案必须包含关键词**：
- "提示"
- "可能"
- "建议关注"
- "不能替代医生诊断"

### 5. 字段要求

- **维度代码**：建议使用标准的维度代码（如：METABOLIC、GLYCEMIC、URINARY等）
- **风险等级**：必须是：低、中、高、极高 中的一种
- **健康评分**：必须在 0-100 之间
- **置信度**：必须在 0-1 之间
